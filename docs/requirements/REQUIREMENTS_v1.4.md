# AI Solo Studio — 需求规格 v1.4（重建基线）

- **文档版本**: v1.4.0
- **日期**: 2026-11-07
- **状态**: 重建基线（`rebuild` 分支）。v0.1/v0.2 演示代码保留在 `main` 分支，不再沿用。
- **历史版本**: v1.2 见 `main` 分支 `docs/REQUIREMENTS_REPORT.md`

---

## 1. 一句话定位

**面向独立创作者的 AI 软件开发与验收工作台：你决定做什么，AI 负责实现，工作台负责证明结果、控制风险、随时可撤销。**

设计哲学：AI 在“实现”上越来越强，但“这个东西对谁有用、用起来对不对”的判断——对人性的理解——仍然属于人。产品把人的判断放在最关键的位置，把 AI 的执行力放在最费力的位置。

## 2. 目标用户

**主画像**：已经借助 AI 做出过一点东西（小网站、小工具），想继续加功能、修问题，却难以掌控的人。

- 会装软件、能登录账号、知道项目文件夹是什么；
- 看不懂 diff，不会处理 Git，看到报错会慌；
- 最大的恐惧：不知道 AI 改了什么、怕把已有成果搞坏、卡住了不知道怎么办。

**非目标（v1.x）**：完全零基础且不愿本地安装的用户；资深工程师。

**MVP 项目范围**：仅支持**本地网页类项目**（可 `npm run dev` / 静态预览的前端或全栈小项目）。

## 3. 核心原则（铁律）

1. **AI 自述不是证据。** 任务状态只能来自真实信号：进程退出码、构建结果、测试结果、用户验收。
2. **状态必须如实。** 区分：`已验证`、`用户已确认`、`未检查`、`失败`。不确定就显示不确定。
3. **默认安全。** 不使用任何跳过权限的参数；执行在隔离分支中进行；高风险操作必须人工批准。
4. **有边界的恢复。** 明确告诉用户什么能自动恢复、什么不能，并在执行**前**提示。
5. **人定方向。** 未经用户批准计划，不修改任何代码。
6. **只走官方支持的集成方式。** 不嵌入、不程序化驱动消费级网页（claude.ai、chatgpt.com）。

## 4. 核心闭环（MVP 唯一目标）

```
提出需求 → (按需)澄清 → 计划卡 → 批准 → 隔离施工 → 验收卡 → 保存 / 撤销
```

### 4.1 提出需求
自然语言描述，可附截图。示例：“给网站加深色模式，不要影响其他页面。”

### 4.2 按需澄清
- AI 判断需求是否存在**影响结果的关键歧义**；无歧义则直接出计划。
- 需要澄清时，最多 3 个问题，选择题优先。

### 4.3 计划卡（Plan Card）
包含：要做什么 / 不做什么、预计影响的文件范围、**验收标准**（用户语言）、风险提示、**恢复边界**（本任务的哪些影响无法自动撤销，如安装依赖、写数据库、调用外部服务）。用户可编辑后批准。

### 4.4 隔离施工
- 每个任务在独立 Git worktree（分支 `studio/task-<id>`）中执行，主线不受影响。
- 项目不是 Git 仓库时，向导说明并经用户同意后初始化，同时创建初始保存点。
- 【已修正（2026-11-08），见 docs/REQUIREMENTS_REPORT.md “勘误与变更”：不做逐条命令审批；在项目层面一次性披露风险，用户可以对单个项目放开限制。以下为原文，保留备查。】执行体的权限请求转为**审批卡片**，附大白话解释与风险等级：
  - 低风险（读文件、在 worktree 内写文件）：可设为本任务内自动批准；
  - 中风险（安装依赖、运行脚本）：默认询问；
  - 高风险（访问 worktree 外路径、删除大量文件、联网、git push）：始终询问。
- 进度以时间线呈现，原始日志折叠。
- **停止**：向执行进程发送真实的中断/终止信号；执行体不支持“暂停后继续”时，界面只提供“停止”，不伪装暂停。
- 超时按任务可配置（默认 20 分钟），超时如实标记为失败。

### 4.5 验收卡（Acceptance Card）

| 检查项 | 证据来源 | 可能状态 |
| :--- | :--- | :--- |
| 执行体正常结束 | 进程退出码 | 通过 / 失败 / 被停止 / 超时 |
| 改动内容 | worktree 相对基线的 git diff | 文件清单 + 大白话摘要 |
| 构建 | 项目 build 脚本（如存在） | 通过 / 失败 / 无此脚本（未检查） |
| 测试 | 项目 test 脚本（如存在） | 通过 / 失败 / 无此脚本（未检查） |
| AI 请求的操作是否都已执行 | 执行体的结构化拒绝记录（种类、命令/路径、风险） | 无拒绝＝已验证 / 有拒绝＝需要用户关注（逐项确认知晓后才可保存） |
| 预览 | 一键启动本地预览 | 用户已试用 / 未试用 |
| 验收标准逐条 | 用户勾选 | 用户已确认 / 已否决 / 未确认 |

- 大白话摘要由 AI 生成，界面明确标注“AI 摘要，仅供参考，以文件改动为准”。
- 构建/测试失败时提供“发生了什么 / 可能原因 / 建议下一步”，可一键发起修复（仍在同一 worktree）。
- 项目没有测试时显示“未检查”，不显示为通过。

### 4.6 保存或撤销
- **保存**：将任务分支合并回主线（遇冲突则不自动解决，提示用户并保留分支），记录为一个保存点。
- **撤销**：删除 worktree 与任务分支，主线不变。
- **历史**：保存点时间线，可回到任一保存点（以新提交的方式回退，不改写历史）。

## 5. 首次使用

1. **环境体检**：检测 Git、Node.js、受支持的执行体 CLI 及其登录状态；红黄绿显示，给出官方安装指引。
2. **选择项目**：打开已有文件夹，或从示例模板创建。
3. **示例任务**：引导用户在 10 分钟内完成一次完整闭环。

## 6. 执行体策略

- 统一 **Executor Adapter** 接口：启动、事件流（消息/工具调用/权限请求/结束）、批准/拒绝、停止。
- MVP 只实现**一个**真实执行体；另提供 **Fake Executor** 用于自动化测试与演示。
- 第一个真实执行体：**Codex（通过 `codex app-server` 接入）**，依据技术验证与条款核查（见 `docs/adr/0001-first-executor-spike.md`）；第二个候选为 Claude Code（仅 API Key 模式）。
- BYOS 表述为“按官方允许的方式使用你已有的 AI 服务”：Codex 用户可按 OpenAI 官方方式使用自己的 ChatGPT 计划；Claude 用户需自备 API Key。不承诺任何订阅无条件可用；README 中如实说明。
- **适配器安全参数**：适配器必须显式传入全部安全参数（沙箱范围、工作目录、审批策略），并隔离用户全局配置。spike 中发现用户配置可能含 `danger-full-access` 或自动允许规则，会改变权限行为。
- **退出码 0 不代表成功**：适配器必须解析结果事件（回合状态、权限被拒记录），不能只看进程退出码；失败或被拒的回合不得报告为成功。
- **中断不回滚**：停止只能阻止后续动作，不会回滚已落盘的那一步；由隔离 worktree 的撤销兜底。

## 7. 非功能要求

- **安全**：Electron `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，渲染进程只通过白名单 IPC 访问能力；子进程一律 `spawn` 参数数组调用，不经 shell；不写死任何个人路径。
- **执行体隔离**：启动执行体时显式传入沙箱（仅工作区可写）、工作目录（任务 worktree）与审批策略（需要时询问或更严格），忽略用户全局配置；禁止任何跳过权限或关闭沙箱的参数。注意部分沙箱默认允许写系统临时目录，worktree 外（含临时目录）的写入一律按高风险处理。
- **执行体隔离的已知限制**（详见 ADR 0001“配置隔离调查与已知限制”）：用户配置的 MCP 服务器、自定义指令、连接器与插件已按会话关闭；但用户目录与项目内的 AGENTS.md 无法被官方方式关闭，hooks/notify/memories 等未逐项验证，未指定模型时沿用用户默认模型。风险：用户全局规则文件可能影响执行体行为。后续计划：按任务分配工具与规则（最小授权），届时重新设计隔离。
- **结果判定**：以执行体的结果事件为准（回合状态、权限被拒记录），退出码 0 不等于成功；中断不回滚已落盘的一步，依靠 worktree 撤销恢复。
- **隐私**：代码与对话只在本机与用户选择的 AI 服务之间流转；无遥测。
- **可测试**：核心逻辑与 Electron 解耦，可在纯 Node 环境测试。
- **可移植**：macOS 优先；Windows 在 v1.0 前验证。

## 10. 明确不做（v1.0 前）
