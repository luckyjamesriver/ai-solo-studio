# 执行体交接协议（PROTOCOL）

适用于所有从 ~/AI-CoWork-rebuild-import/ 领取任务的执行会话（内部执行与外部执行交接使用同一协议）。开工前必须完整阅读并遵守。
版本：v1.5 加强版（依据 docs/requirements/REQUIREMENTS_v1.5.md 第 7 节）。

## 开工前
1. **确认任务编号**：next-task.md 顶部的“任务编号”必须与用户在指令中给出的编号一致；不一致则停止并询问用户。
2. **检查锁**：若 task.lock 已存在，先核实，不要直接覆盖或删除：
   - 读取锁内容，用其中的 PID 检查持有进程是否仍在运行（`ps -p <PID>`），并核对其会话名称与工作目录；
   - 持有进程仍在运行 → 锁有效：停止，告诉用户锁内容，等待指示；
   - 持有进程已不存在（过期锁）→ **不得静默覆盖**：把锁内容与核实结果告诉用户，询问恢复、接手还是释放。
3. **加锁**：创建 task.lock。锁按**项目、任务、工作树**定义所有权，至少记录：项目、任务编号、工作树路径、会话名称、进程标识（PID）、开始时间、当前状态、起始 Git HEAD。
4. **阅读背景**：docs/PROJECT_CONTEXT.md；以及任务中提到的其他参考文件。
5. **检查工作目录状态**：在 ~/ai-solo-studio-rebuild 运行 `git status` 与 `git log --oneline -5`。若有未提交改动或出现你不认识的新提交，停止并报告，不要继续。

## 执行中
- 只做任务文件中列出的事；发现任务外的问题，记录进报告，不顺手修改。
- 每项单独提交；未经用户确认不推送。
- 遵守通用约束：不碰 ~/AI-CoWork；不改任何用户全局配置；不读取、复制或转发任何登录凭证；禁止跳过权限或关闭沙箱的参数；tests/security.test.ts 只增不减。
- 每完成一项就验证（typecheck、test、build、smoke），并更新 task.lock 中的“当前状态”并追加一行进度。

## 必须停下来问用户的情况
- 锁冲突、任务编号不符、工作目录有陌生改动；
- 需要跨大版本升级依赖，或需要修改安全设置；
- 任务要求与本协议或 PROJECT_CONTEXT 中的原则冲突；
- 同一个问题尝试三种方法仍未解决；
- 任何需要接触凭证、联网上传或访问工作目录以外位置的操作。

## 收尾
1. 覆盖写入 ~/AI-CoWork-rebuild-import/report.md，**第一行写任务编号**，然后按任务要求汇报：改动、证据、测试结果、未解决问题、提交哈希。报告必须绑定 Git 状态：
   - 开始与结束时的 Git HEAD；
   - 工作树路径（及其 HEAD，若使用了独立工作树）；
   - 测试证据（命令与结果数量）；
   - 产物版本（新增提交哈希、文档版本）。
2. 删除 task.lock（只删除自己创建的锁）。
3. 在对话中告诉用户：“任务 <编号> 已完成，报告已写入 report.md”，并给出三行以内的摘要。
