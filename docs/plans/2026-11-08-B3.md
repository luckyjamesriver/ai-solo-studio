# B3 定稿候选：施工模式与授权（依据 B3-0 实测 + ChatGPT 评审 R01–R11 + 维护者决定）

起草：规划会话，2026-11-08。取代 B3-approval-model-draft.md。待维护者批准（含放宽两条安全断言）后写 B3-1 任务。

## 0. B3-0 实测带来的三个关键事实
1. **读取可以事前阻止**：Codex 官方“权限配置档”（default_permissions + permissions.<id>，文档标 Beta）的 deny 由 macOS 系统沙箱强制（不经模型的 command/exec 实测 `Operation not permitted`）。评审 R01 的根本问题有了技术解。
2. **施工中的越界审批是“整条命令脱离沙箱”**：on-request 下，批准一次 = 这条命令在沙箱外运行（reason 原文“rerunning … outside the sandbox”），且可选项里带“以后都允许”。它无法被收窄成“只多给一点”。评审 R05 成立。
3. **普通任务越界 0 次**：改网页标题并跑测试，全程无审批事件。

## 1. 结论：施工中不再有任何审批
- 取消“施工中决定卡”。**所有授权在开工前一次完成**，施工中 AI 碰到边界就失败，并如实写进结果；需要更多权限时，任务结束后由用户在“扩展权限”里加上再重跑或让 AI 修复。
- 这同时满足：维护者硬要求（不逐条打断、不显示命令）、评审 R05（不让用户批准无法说清范围的东西）、R07（严格与默认合并，不再有名不副实的两档）。

## 2. 两种模式
### 2.1 标准模式（默认）
- Codex 使用权限配置档：可写=任务副本（及按需的显式额外目录）；**读取拒绝清单**（见 2.3）；网络默认关闭；审批策略 never（越界直接失败，不挂起——已实测）。
- **扩展权限**（开工前在计划卡勾选，系统强制，不是靠 AI 自律）：
  - 允许联网（如安装依赖）——如实说明“开启后可访问任意网站”（域名级限制 B3-1 实测，做不到就如实写）；
  - 允许写入用户选定的另一个文件夹（追加为可写目录）。
  - 不提供其他扩展项；做不到技术强制的一律不提供（评审 R03 建议）。
- 每次开工记录**实际生效**的权限（以 thread/start 返回的 activePermissionProfile 与网络状态为准），不沿用项目偏好静默放大（R09）。

### 2.2 完全信任模式（维护者 2026-11-08 决定保留）
- 如实命名与风险说明（AI 拥有你账户的全部权限；可读任何文件、联网、改项目外文件、可能自行推送；读到的内容发给 AI 服务商；项目外改动不可撤销）。
- 每个任务开工时单独确认；项目只记偏好；关闭须等旧进程退出才显示生效。
- 该模式下不承诺“推送只由你做”“凭证不发给 AI”。
- 对应 danger-full-access + never（已实测可用）。

### 2.3 读取拒绝清单（标准模式）
- 首选：拒绝整个用户主目录，只放行任务副本与必需路径（B3-1 实测：deny 主目录后，主目录内的副本能否仍被允许；Codex 自身能否正常运行）。
- 退路：固定敏感清单（~/.ssh、~/.aws、~/.config 中的凭证类、钥匙串、~/.codex 下的 auth 与 skills、项目外的 .env 类、浏览器资料等）。用退路时界面如实写“已阻止读取这些敏感位置；其他位置 AI 仍可读取”，不得称“已隔离”（R01）。
- B3-0 发现 Codex 会自己读 ~/.codex/skills 下的文件并发给 OpenAI：B3-1 实测 deny 该目录是否可行、是否影响 Codex。

## 3. 项目脚本（build / test / preview）进入同一沙箱（R06）
- 宿主不再自己直接 `npm run`，改用 app-server 的 command/exec 在**同一权限配置档**下运行（B3-0 已证实 command/exec 受沙箱约束）。
- 开工前在计划卡列出将运行的脚本（绑定内容摘要）；网络随扩展权限；环境变量最小化。
- 预览需要监听本机端口：B3-1 实测沙箱内能否监听 127.0.0.1；不能则预览标“需要完全信任模式或手动预览”，不偷偷在沙箱外运行。
- 若受限环境不可用 → 标“未检查”，不降级为宿主权限运行。

## 4. 结果与证据（承接 B4）
- “被拒/失败的操作”：严格（never）下失败并不总有命令事件（B3-0：2/2 无事件）。因此验收卡写“AI 报告以下操作未能完成”（标明是 AI 自述）+ 宿主可验证的事实（检查是否通过、改了哪些文件），不把命令事件当完整记录（R02）。
- “AI 查看过的项目外文件”：只在完全信任模式下显示，标“已观察到的访问，可能不完整”（R02）；标准模式靠事前拒绝。
- 成品界面任何位置不显示原始命令（R08）；诊断记录仅本机保存，不自动展示、不外发。

## 5. 需维护者批准：放宽两条安全断言
现有适配器与 security.test.ts 禁止 `never` 与 `danger-full-access` 字样。改为：
- `never` 只允许出现在模式映射模块（标准与完全信任两处），其他位置仍禁止；
- `danger-full-access` 只允许出现在完全信任映射，且该路径必须经过“本任务已确认完全信任”的门禁函数（新增断言检查调用链）；
- 新增断言：任何地方不得使用 acceptWithExecpolicyAmendment（“以后都允许”）；审批回调在标准模式下只能拒绝。

## 6. B3 拆分
- **B3-1（实测 + 核心，无界面）**：主目录整体 deny 的可行性、~/.codex/skills deny 的影响、网络域名限制能否做到、沙箱内监听本机端口、xcrun 噪音处理；适配器改用权限配置档、两种模式映射、生效权限核验、command/exec 运行检查脚本；断言按第 5 节修改。
- **B3-2（界面）**：计划卡上的模式与扩展权限、完全信任风险确认、施工进行中视图（只停止）、结果中的“未完成操作”。

## 7. 评审意见处理对照
