# M3-B 方案（定稿候选，待维护者批准）

依据：M3-B-plan-draft.md + ChatGPT 独立评审（11 条，2026-11-08，结论“方向通过，实施方案需修改”）。
规划者已核对评审引用的源码：R02（checks/scripts.ts 直接 `npm run`，且 env 继承整个 process.env）与 R06（risk.ts 中 worktree 内 write_file 为 low+reversible，autoLow 会自动批准写入）属实。

## 0. 目标（不变）
会装软件、看不懂 diff 的创作者，能在桌面应用里独立完成：提需求 → 批准 → 隔离施工 → 看证据验收 → 保存或撤销，不开终端、不懂 Git。
产品原则（采纳评审表述）：**不靠增加审批制造安全感，也不靠减少审批牺牲安全；自动处理真正安全的事，只在需要人作判断时请人介入。**

## 1. 顺序：B1 → B3 → B4 → B2（采纳 R05）
B3/B4 先用固定测试计划（FakeThinker 或手写计划卡）驱动，做出“可施工、可验收”的纵向切片；B2 最后接入真实思考层。每个子任务独立验收。

## 2. 评审意见处理结果（六字段的“处理结果”）

| R02 自动 build/test 绕过审批 | 阻断（已核实） | **已采纳**：项目脚本（检查与预览）统一授权边界。计划卡中逐项列出将运行的脚本及其内容，用户批准后才可运行；授权绑定脚本内容摘要，内容变了即失效。运行时环境变量改为最小白名单（PATH、HOME、语言等），不再继承整个 process.env。macOS 上本轮**没有真正的进程隔离**，界面如实说明“项目脚本以你的身份运行”；未授权就显示“尚未检查”。 | B3 |

| R05 子任务顺序 | 建议 | **已采纳**，见第 1 节。 | — |
| R06 风险等级与自动批准未分离 | 阻断（已核实） | **已采纳**：拆成两个判定——风险等级（给用户看）与“是否允许自动批准”（单独规则，需同时满足具体操作、路径、授权范围）。M3-B 中自动批准规则为空集；无法分类的请求默认询问。另修正：`npm run` 项目脚本不应标为可完全恢复。 | B3 |

| R08 两秒延迟不是有效防护 | 建议 | **已采纳**：取消固定延迟。高风险审批卡必须回答：它想做什么、会影响哪些文件/数据/服务、能否撤销、拒绝后能否换安全做法；提供“拒绝并请 AI 换方法”。不可恢复或外发数据的操作要求选择授权范围（仅本次）。疲劳统计增加：事后复核时用户是否认同自己当时的决定（M3-C 收集）。 | B3 |

## 3. 各子任务交付边界
- **B1 入口与环境**：打开项目（对话框、非 Git 引导初始化、最近项目）；分层体检（Git、Node 与项目声明是否一致、npm、Codex 安装/版本/登录状态、GUI 启动时的 PATH）；首次使用的外发告知。不做配置中心。
- **B3 施工与审批**：用固定计划卡在 worktree 中跑 Codex；进行中视图（AI 自述标注“不是证据”、实时改动文件）；只提供停止；风险等级与自动批准拆分（自动批准为空）；新审批卡（R08）；项目脚本授权边界与最小环境变量（R02/R07）；被拒操作入验收卡；审批统计本机记录。
- **B4 验收与恢复**：证据先行的验收卡（改动 → 预览 → 检查 → 被拒与未完成 → 最后逐条确认验收标准）；内容冻结与保存前复核（R03）；受控预览（R09）；保存、冲突处理（放弃或让 AI 修复）、撤销、回到保存点；验收摘要写 docs/changelog/。
- **B2 计划整合**：接入 M3-A2 引擎；上下文选择与外发检查（R04）；需求条目确认、分歧裁决、方案批准 + 开工批准同页（R11）。

## 4. 测试与验收
- 自动化（Playwright + Fake 执行体/思考者）必须覆盖：正常保存；撤销后原项目不变；高风险请求被拒并让 AI 换方法；执行失败不虚报完成；执行中停止；审批请求与停止同时发生；预览进程残留；保存前文件被改动；主线出现新提交；关闭窗口后重开恢复。
- 安全断言只增不减；新增渲染进程 API 逐个列入安全测试；新增：自动批准规则在 M3-B 为空的断言、检查脚本不继承完整 process.env 的断言。
- 维护者本机验收：在一个小网页项目上用 Codex 完成 4 类场景——正常开发、不满意撤销、高风险请求、执行失败——不开终端。
- 明确：维护者跑通只证明内部闭环可运行，**不证明入门用户能独立使用**，后者属于 M3-C。
