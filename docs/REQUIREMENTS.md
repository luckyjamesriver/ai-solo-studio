# AI Solo Studio (ai-solo-studio)
## 产品需求规格与系统设计说明书 (Product Requirements & Architecture Specification)

- **版本**: v1.0.0
- **编制日期**: 2026-11-06
- **定位**: 专为独立创作者（Solo Creator）与非 IT 程序员打造的多 AI 协同虚拟工作室与执行指挥中枢
- **状态**: 正式基线文档 (Active Baseline)

---

## 1. 项目诞生背景与核心问题 (Problem Statement)

### 1.1 行业现状与创作者痛点
当前的 AI 辅助开发与多 Agent 平台（如 AutoGen、CrewAI、Docker 化工作流、纯命令行 Agent）基本是**“程序员做给程序员用的”**，存在以下核心痛点：
1. **认知门槛极高**：面对纯黑屏终端、复杂的 Git 冲突解决、冗长的系统环境变量配置，非 IT 背景的独立创作者望而却步；
2. **单 AI 聊天存在严重局限**：
   - 官方网页端（ChatGPT / Claude）虽然交互友好，但处于云端封闭沙盒中，**天然无法读写本地代码、无法执行编译测试**；
   - 单一模型容易出现逻辑幻觉、自说自话，缺乏批判性思考与风控审查；
3. **“手脑混杂”导致工程失控**：让同一个大模型既充当产品经理规划蓝图，又同时在同一个上下文里写几千行代码，上下文窗口迅速耗尽，逻辑混乱；
4. **API Token 费用昂贵**：市面上的商业多 Agent 平台大多要求按 Token 付费，而独立创作者本身往往已经按月订阅了 ChatGPT Plus、Claude Pro 或 Cursor 等服务，重复计费成本极高；
5. **缺少“指挥与控制系统”**：现有工具（包括纯 MCP 连接器如 WebCodex）大多只是“被动的工具通道”，无法做到把复杂方案拆解成多阶段工单，并指挥各个专业执行体分工施工。

### 1.2 产品的核心愿景与使命
打造一款让创作者**“喝着咖啡、用大白话交流，就能指挥顶尖 AI 智囊团和工程施工队把 Idea 落地为真实软件”**的桌面中枢：
- **把战略讨论留给顶尖双脑（Claude + ChatGPT）**；
- **把繁重编码与测试留给底层工匠执行体（Cursor Agent + Antigravity）**；
- **把最高控制权与拍板权留给人类创作者（紧急暂停 + 里程碑确认）**。

## 3. 核心功能规格说明 (Functional Specifications)

### 3.1 战略研讨室 (War Room - 双 PM 协同)
1. **联合司令部模式 (Dual PM Consensus)**：
   - 用户在输入框提出一个需求，系统自动并行激活 **Claude** 与 **ChatGPT**；
   - Claude 从产品定位、架构层次、模块拆解角度给出规划；
   - ChatGPT 从安全性、并发瓶颈、异常边界、逻辑盲区角度进行审阅与补位；
   - 系统自动将双方推演结果合成并在右侧 **Canvas** 实时生成《双脑共识架构与开发规范书 (SPEC)》。
2. **单兵深入咨询模式 (Single PM Consultation)**：
   - 支持受话方快速切换：可单找 Claude 深入推敲设计，或单找 ChatGPT 核查特定逻辑。
3. **真实模型与思考深度调节**：
   - 彻底摒弃硬编码猜测，动态探测本机可用的真实模型（如 `gemini-3.8-flash-high`、`gpt-5.6-sol`、`claude-sonnet-5-5` 等）；
   - 支持设置思考级别（低 / 中 / 高深度思考）。

### 3.2 创作者特权通道 (Human-in-the-Loop)
1. **🔴 紧急暂停通道 (Emergency Pause)**：
   - 界面显著位置提供“暂停”按键，创作者可在任意时刻冻结当前执行流程；
   - 允许创作者插话纠偏，调整大方向后再恢复执行。
2. **🟡 里程碑拍板机制 (Milestone Checkpoint)**：
   - 双脑推演完成后，绝不擅自执行修改本地代码的高危动作；
   - 在界面弹出确认卡片，展示核心工单概览；
   - 只有当创作者亲自点击【批准开工 (Approve)】后，任务才正式下发至底层执行体。

### 3.3 规范画布与工单看板 (Canvas & TaskBoard)
1. **规范文档画布 (Canvas)**：
   - 渲染 Markdown 规范书；
   - 支持一键切换【对比 (Diff)】模式与【源码 (Source)】模式；
   - 具备自适应工具栏，确保在分屏窄屏下按钮不折行、不被挤压变形。
2. **三态工单看板 (Task Board)**：
   - 自动提取阶段性工单（如：Phase 1 环境与骨架、Phase 2 核心功能开发、Phase 3 自动化测试与验证）；
   - 展示每个工单的指定执行体（Cursor / Antigravity）、当前状态与进度报告。

### 3.4 底层执行体监控 (Live Worker Runner)
1. **多执行体独立 Tab 监控**：
   - 提供全部汇总流，以及 Cursor Agent、Antigravity、Claude Code、Codex 独立选项卡；
   - 实时采集后台进程的标准输出（stdout）与错误输出（stderr）。
2. **直接调度与交互验证**：
   - 支持在受话方中选择“直通 Cursor”或“直通 Antigravity”，直接向底层工匠下发即时操作指令，并快速获得真实反馈。

### 3.5 双模视界：联合中枢 vs 官方原生 (Dual-View Interface)
1. **联合中枢 (War Room View)**：三栏分层工作台（左侧项目与会话树、中间双脑研讨、右侧画布与执行流）。
2. **官方原生并排视界 (Official Webview View)**：
   - 利用 Electron 的持久化 Session (`persist:ai_solo_claude` 与 `persist:ai_solo_chatgpt`)，内嵌官方原生 `claude.ai` 与 `chatgpt.com`；
   - 支持免额外登录复用网页端 Plus / Pro 订阅；
   - 提供“一键复制工程上下文”与“网页方案一键导入回中枢 Canvas”快捷按键。

### 3.6 项目级轻量 MCP 桥梁 (Project-level MCP Bridge) —— *吸收 WebCodex 优势*
1. **单项目 MCP 服务**：
   - Studio 为当前活动项目生成本地 MCP Server 接口；
2. **云端官方聊天感知本地**：
   - 允许创作者将生成的安全 MCP URL 挂载到 ChatGPT 开发者模式或 Claude 客户端；
   - 实现创作者在官方聊天窗口打字时，云端 AI 能直接透传检查本地目录与运行测试；
3. **聊天成果回流**：
   - 官方对话中讨论确定的代码方案，可一键导入到 Studio 看板中，派发给本地执行体落地。

## 4. 关键技术约束与安全规范 (Technical Constraints & Guardrails)

1. **自带订阅原则 (BYOS - Bring Your Own Subscription)**：
   - 严禁强行绑定商业付费 API Gateway；
   - 优先复用本机合法已安装的官方 CLI 工具（`/Users/jamesho/.local/bin/agy`、`cursor`、`claude`、`codex`）；
   - 优先复用本地 Electron Partition 保存的官方网页凭据。
2. **真实探测原则 (Zero Guesswork)**：
   - 严禁在界面硬编码虚构或不存在的 AI 模型；
   - 必须通过接口动态读取本地 CLI 支持的真实模型列表。
3. **工作区安全隔离 (Workspace Isolation)**：
   - 试验性项目或示例生成必须限制在隔离目录（如 `workspace/`）下；
   - 执行体严禁在未经用户明确指定的情况下，修改外部用户既有重要工程仓库。
4. **干练输出原则 (Clean & Direct Output)**：
   - 日志系统仅保留关键业务流向与真实输出（如 `Antigravity：“...”`）；
   - 禁止在用户日志中堆砌冗长无用的机器包装文本与套话。
5. **健壮性与超时控制**：
   - CLI 进程调用必须设置合理超时（默认 90 秒），防止死锁；
   - 进程执行必须加入非交互式免打扰参数（如 `--dangerously-skip-permissions`、`--trust`），防止后台静默挂死；
   - 严禁在超时后使用伪造的“执行成功”虚假占位字符串掩盖异常。
