# M0 + M1 本机验收清单（macOS）

在你的 Mac 上逐项执行，全部打勾即视为 M0/M1 通过。

## 安装与自动化测试
- [ ] `npm install` 成功
- [ ] `npm run typecheck` 无错误
- [ ] `npm test` 全部通过（应为 44 项）
- [ ] `npm run build` 成功

## 桌面外壳
- [ ] `npm start` 能打开窗口，标题为 AI Solo Studio
- [ ] “你的电脑准备好了吗”中 Git、Node.js 显示为绿色
- [ ] 点击“打开项目文件夹”，选择一个**没有** Git 的测试文件夹（例如新建 `~/studio-test`，放一个 index.html）
- [ ] 看到开启版本记录的说明；点击后出现“studio: 初始保存点”
- [ ] 在终端确认：`cd ~/studio-test && git log --oneline` 有一条提交，index.html 内容未变
- [ ] 打开一个**已有** Git 的项目，能列出最近的提交作为保存点，且不提示初始化

## 安全
- [ ] 在窗口中按 `Cmd+Option+I` 打开开发者工具，Console 中输入 `typeof require` 和 `typeof process`，结果都为 `"undefined"`
- [ ] Console 中输入 `Object.keys(window.studio)`，只有 4 个函数

> 以上“安全”各项（`typeof require`、`typeof process`、`window.studio` 只有 4 个函数）以及窗口标题、Git 体检为绿色，可用 `npm run smoke` 自动检查（通过 DevTools 协议读取页面，失败时退出码非 0）。

发现问题请记录：现象、操作步骤、截图。

## 依赖版本策略
- 运行时（Electron）和所有依赖都固定精确版本号，不使用 `^` / `~`。
- 升级时，选择受支持大版本中**发布满两周**的最新补丁版本（用 `npm view <包> time` 确认发布日期），并在提交说明中写明版本、发布日期和来源。
- 禁止使用 `npm audit fix --force`。
- 跨大版本升级必须单独提交，并在提交说明中写清理由。
