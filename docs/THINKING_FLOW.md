# 思考流程与外部执行交接（M3-A2）

纯 Node 的最小思考流程引擎 + 命令行入口；没有界面（界面是 M3-B）。依据需求 v1.5 第 3、7、8 节。

## 用法

```bash
npm run think -- "<需求>" --task <任务编号> --export-dir <目录>     # 新线程
npm run think -- --resume <线程编号> --task <任务编号> --export-dir <目录>
npm run think -- --import <report.md> --task <任务编号>              # 导入并核对报告
```

选项：`--single`、`--planner <id>`、`--reviewer <id>`、`--set-current`、`--context <文件>`、`--project <目录>`、`--max-calls`、`--step-timeout`、`--max-total`、`--max-cost`。

- **预设 `dev-personal`**（未指定思考者时使用）：Claude 本机登录规划 + Codex 评审。这是**开发者自用预设，不是产品默认**。需要 `STUDIO_DEV_PERSONAL_CLAUDE=1`。预设不可用时报错并列出可用思考者，**不会**自动改用其他规划者。
- 没有交互终端（无 TTY）时，所有需要你确认的点都会停止并保存线程，不会默认通过。

## 流程

线程状态：`requirements_draft → requirements_confirmed → drafted → reviewed → revised → awaiting_approval → approved → task_exported`；终止态 `stopped`（附原因）、`rejected`。

**线程状态与调用尝试分开**：每次调用思考者是一条独立的尝试记录；只有 `status=complete` 且结构解析成功（并通过宿主的结构检查）的尝试才产生带版本号的正式产物。尝试失败时线程状态不前进、已有产物全部保留、不自动重试、不自动换模型；你可以重试、补充说明后重试，或终止线程。重试产生新尝试，不覆盖旧记录。

1. 规划者把原始需求拆成条目（R1、R2…）→ **暂停交你确认**（可增、删、改；回车 = 原样接受）→ 冻结。冻结后思考者无权修改条目；若输出试图修改，被忽略并记录。
2. 规划者起草（对每个冻结条目给出覆盖说明）→ 评审者独立评审（六字段意见 + 逐条目检查 + 需要的证据）→ 规划者修订（逐条填处理结果、逐条目标注保留/修改/删除、新增内容单列）。默认一轮评审、一次修订；第二轮暂未实现（只能由用户显式触发，本轮不提供触发入口）。
3. 宿主机械检查（不依赖模型自报）→ 你逐项裁决 → 批准 → 方案写入 `docs/plans/<日期>-<线程编号>.md`（不自动提交）→ 导出任务文件。

评审者收到：冻结条目、原始需求、必带层上下文（PROJECT_CONTEXT 第 1、2、4 节）、你指定的按需资料、规划者的**方案正文**；**不**收到规划者的原始输出全文与推理。每次调用的发送清单（名称、字节数、层、服务名）写入尝试记录。首次向某服务发送资料时提示“资料将离开本机发往 <服务>”并要求确认，按服务记录在 `.studio/consent.json`。

## 机械检查：能做什么、不能做什么

- **范围比对**：只比对“冻结条目是否被修订稿逐条标注”。遗漏、标注删除、出现新增内容 → 列出差异，必须由你逐项裁决。**不做语义判断，不判断变化是否“实质”。**
- **依据核验**：区分“提供了依据”与“依据已核验”。依据为空/“无” → 未经证实；引用的本地文件（可含 `#章节标题`）不存在 → 依据无法核实；文件存在 → 只表示文件存在，**不代表内容支持该意见**；其余一律维持未经证实。
- **阻断规则**：处理结果为“未解决”或“交用户裁决”的阻断意见，必须你逐条裁决（接受/驳回 + 一句理由）才能批准。
- **安全检查**（发送清单缺失、思考者请求了工具、隔离证据异常）未通过时，不提供“批准”选项；你驳回某个范围差异时同样不能批准。

## 停止条件与预算（如实表达）

每线程调用次数上限、单步超时、累计调用耗时上限，以及可选的累计已知费用上限。**发起每次新调用之前**检查累计已知消耗。ClaudeCli 使用结果事件里的费用；Codex 只记调用次数，不虚构金额。**单次调用的费用无法事前封顶**：预算是“累计到达即不再发起新调用”，不是硬上限。任一条件触发 → `stopped` 并说明原因，保留全部正式产物。

## 产物存放

- 过程记录：`.studio/threads/<线程编号>/`（不入库）。入口检查 `.gitignore` 是否包含 `.studio/`，没有则提示，**不自动修改**。
- 恢复时校验每个正式产物与记录中的版本、sha256 一致；不一致即停止并报告，不使用该产物，线程状态不变。
- 所有写入由宿主完成；思考者没有写权限。`docs/adr/`、`docs/changelog/` 本轮不写。

## 外部执行交接

**导出**：生成符合 `docs/PROTOCOL.md` 的任务文件（首行任务编号；单思考者时标注“未经独立评审”）。同时生成任务清单 `.studio/tasks/<任务编号>.json`（仓库根路径、分支、工作树路径、起始 HEAD、批准方案路径与版本摘要、导出时间、任务文件摘要）；已存在则拒绝覆盖。默认导出为 `<导出目录>/<任务编号>-task.md`（临时文件 + link，不覆盖）。只有加 `--set-current` 才更新 `next-task.md`：已存在时显示其首行并要求确认，旧文件另存为 `<旧编号>-task.md`（同名已存在则不覆盖并提示）。导出目录由参数给出，代码里不写死任何路径。

**导入**：按任务清单核对报告：首行任务编号、仓库、分支、工作树、开始 HEAD 与清单一致；结束 HEAD 存在且是清单开始 HEAD 的后代（相同也算，会注明“没有新提交”）；并如实列出工作树当前的未提交与未跟踪改动。结果三档：**已绑定**、**不符**（列出矛盾项）、**来源未核实**（报告缺绑定信息，或找不到任务清单）。只有“已绑定”可调用规划者审查一次，结果交你；“不符”与“来源未核实”只能只读查看，不能产生验收通过，不能触发保存或下一个任务。

> **Git 关系正确只证明版本关系，不证明任务完成；报告内容与测试证据仍需审查。** 规划者的审查只是意见，不是验收通过；不会自动派下一个任务。
