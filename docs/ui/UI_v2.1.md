# AI Solo Studio 界面设计 v2.1（已冻结）

- 状态：**冻结**（2026-11-10）。经 ChatGPT 两轮评审（v1 → v2 → v2.1），维护者批准。
- 可点击原型：[`docs/ui/prototype.html`](prototype.html)（单个文件，用浏览器打开；顶部目录和按钮都可跳转）。
- 设计源文件：claude.ai 上的设计画布（维护者私有）。本目录是给执行者使用的正式副本，以本目录为准。
- 修改规则：冻结后改动界面结构、流程或文案原则，需要先修改本文档并经维护者批准；实现中的视觉微调（间距、对齐）不需要。

## 0. 实现时最重要的一条

**界面上的每一个承诺都必须有后台支撑。** 允许用户承担经过明确告知的风险，但不能把「未知」显示成「成功」，也不能承诺系统没有验证过的数据安全。第 8 节列出了本设计依赖、但现有代码**尚未实现**的后台能力；它们没做完之前，对应界面不得上线，或者必须改为如实的文案。

## 1. 导航结构

三级：**工作台 → 项目 → 任务**。

- **左侧栏**（所有页面相同宽度，可手动收起，不随页面自动变化）：
  - 「待我处理」+ 角标（只计需要用户处理的数量，不是任务总数）
  - 「我的项目」列表，每个项目一个角标（橙色表示有异常）；「＋ 打开项目文件夹」
  - 底部：一行额度状态（详情在设置里）；「设置」
- 多个项目可以同时打开，切换项目不关闭其他项目。
- 环境体检不再常驻页面：首次使用时作为引导；之后只在检测到问题时，作为一条「出了问题」出现在「待我处理」。

## 3. 状态模型

- **阶段**：讨论 / 施工 / 验收 / 已结束。
- **运行状态**（卡片上的标签）：运行中、等你裁决、等你验收、已暂停、已停止、已中断、失败、被阻断、外部执行中（等待导入报告）、已锁定（项目状态异常）。
- **结局**（仅「已结束」）：已保存、已放弃、未完成而终止。
- 卡片信息固定顺序：任务名 → 当前状态 → AI 与辅助信息。

## 4. 讨论阶段

- 默认布局 **A：标签页**——「方案摘要」「与首席对话」「与复核对话」「评审记录」。宽屏可切换为 **B：两个对话并排**（窗口不足 1100px 时退回 A）。
- 方案摘要页：
  - 「需要你裁决」放最上面，每条写明**接受会怎样 / 驳回会怎样**。
  - 需求条目带版本号（冻结后不可改）；「修改需求」生成新版本，方案按新需求重新起草和评审。
  - 「批准方案」在有未裁决意见时不可点，并说明原因。
- **独立评审规则**：
  - 复核的正式评审只以冻结的方案正文为输入；原件保存在「评审记录」，之后不被覆盖。
  - 每个 AI 的对话只含用户和该 AI 的往来，不自动带入另一个 AI 的内容。正式评审结果按规则交给首席修订——这是唯一的传递通道。
  - 评审之后用户在复核对话里的讨论，标注「评审后的讨论 · 非独立评审」。
  - 对话里的新想法要通过「修改需求」才进入方案，不会改变已冻结的条目。
  - 用户驳回的重大意见，连同理由一直保留在任务记录和验收页，标为「你已知晓并接受的风险」。
- 思考者只能对话，不获得任何工具或文件权限（需求 v1.5 §3.2）。

## 5. 施工计划确认与授权

- 内容：要做什么、预计改动范围、验收标准（可编辑）、权限、执行者、自动检查。主按钮「批准并开工」；次按钮「导出给外部工具执行」。
- **安全模式只有两种**：标准模式、完全信任模式。「允许联网」「允许修改另一个文件夹」是标准模式下的附加权限。完全信任模式开工前另行确认风险（每个任务一次）。
- 「项目级一次性披露」与「任务级确认」的关系：**待裁决**，本版按现有实现，不改授权模型。项目风险说明只是阅读告知，不等于批准以后的任务。
- **另一个文件夹**：勾选后必须显示具体路径和读写范围，并明确说明：它**不在副本里**，AI 会直接修改，施工中就会变化；停止、放弃、撤销都**无法还原**。提供「改为只读」。
- **修改验收标准**：只改措辞可直接保存；新增或改变要求，回到讨论阶段由首席确认方案，不得悄悄扩大施工范围。
- **外部执行**：说明导出的只是任务说明，外部工具不受本应用的隔离与权限保护；导入报告后仍要在本应用验收，导入不等于通过（ADR 0009、PROTOCOL）。
- 碰到未授权的边界：那一步被拦下，任务继续，原因和影响写进验收结果（B3 现行行为）。施工中不做逐条命令审批。

## 6. 验收

- 主区顺序：**成果预览**（电脑 / 手机）→ **检查与证据**（构建、测试、被拦下的操作及影响、改动文件，均可「查看依据」）→ AI 自己的说法（标注仅供参考）。
- 右侧：验收标准（逐条确认）→ 按钮。
- **验收状态**：
  - 验收通过（全部标准确认符合）→「验收通过并保存」可点。
  - 验收未完成（有标准未确认）→ 保存不可点。
  - 验收未通过（有标准确认不符合）→ 主按钮变为「退回修改」。
  - **v1.0 不做部分验收。** 保存记录里不出现「部分通过」（与 `save-rules.ts` 现行规则一致）。
- 其他按钮：退回修改、暂不处理、放弃。
- 证据只来自本应用自己的运行记录。没有检查可跑时显示「未检查」，不能因 AI 自称测过而标为通过。
- 原始记录过滤命令行、密钥、路径等后再显示「详细记录」；完整原始记录只存在本机任务记录中。
- 退回修改后任务显示「第 N 轮」，验收页可切换查看各轮成果与证据。

## 7. 保存、冲突、撤销

**保存前检查**（固定位置，逐步显示结果）：
1. 验收期间项目是否有变化；
2. 合并两边的改动；
3. 合并后重新运行检查；
4. 写入前再确认一次没有新改动。

**结果**（同一位置只显示一种）：已保存 / 未检查（已合并但无检查可跑，不得说「安全」）/ 检查失败（未保存）/ 冲突 / 保存失败·已安全恢复（已核对与保存前一致）/ 保存失败·恢复未确认（停止一切写入、保留恢复点、列出受影响文件、恢复核对前该项目禁止新的保存）。

**冲突**：推荐「让 AI 在最新项目上重做这部分」。「以这个任务为准」必须先进入「查看影响并确认覆盖」：列出被替换的已保存改动、可能失效的验收标准、覆盖后的重新检查结果。

**撤销**：先显示影响范围（之后的哪些保存改过相同部分）；撤销后重新检查，不通过或无法确认安全就不执行、不改任何文件。撤销本身作为一条新的保存记录。**不承诺撤销后一定可以再恢复。**

已知局限（如实告知，不在界面上夸大）：「改了不同文件但逻辑互相影响」只能靠合并后的检查发现；没有检查的项目只能显示「未检查」。

| 能力 | 现状 | 用于 |

## 9. v1.0 不出现在界面上的内容

AI 施工中的截图与实时证据汇总、DeepSeek 接入、预算与成本设置。设计稿中以虚线框表示的内容，真实界面一律不显示，不放不可用的按钮或空白占位。
