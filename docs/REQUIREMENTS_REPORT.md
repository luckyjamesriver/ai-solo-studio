## 1. 概述与核心使命 (Executive Summary & Mission)

### 1.1 诞生背景
当前大语言模型（LLM）与代码智能体（AI Coding Agent）正经历爆发式演进，从 Claude 3.7 / Opus、GPT-5.6 / 6 到 Cursor Agent、Antigravity，AI 编写代码的能力已达到甚至超越资深工程师水准。

然而，对于广大的**独立创作者、独立开发者、产品设计师、以及非 IT 背景的业务创始人**而言，将一个朴素的“商业 Idea”落地为真正可运行的软件产品，依然横亘着一道不可逾越的天堑：
- 面对黑屏命令行 Agent（如 Claude Code CLI、Codex CLI），非技术人员根本不知道如何配置环境、解决 Git 冲突或处理构建报错；
- 面对云端聊天窗口（如 ChatGPT.com、Claude.ai），AI 处于封闭沙盒中，**天然看不见、改不了本地工程代码**，且单模型自言自语极易产生逻辑幻觉；
- 面对商业自动化多 Agent 框架（如 CrewAI、AutoGen），几乎全都强制要求昂贵的商业 API Token 计费，配置繁琐，且依然是“程序员做给程序员用的底层框架”。

### 1.2 产品的核心使命
AI Solo Studio 的核心使命是：**“让创作者喝着咖啡、用大白话交流，就能指挥由顶尖 AI 组成的智囊团与施工舰队，零代码门槛把 Idea 变成高质量软件。”**
- **战略层（脑）**：顶尖双脑（Claude + ChatGPT）坐在一张会议桌上研讨、挑刺、相互审阅，生成高标准规范书；
- **施工层（手）**：底层的专业工匠（Cursor Agent + Antigravity）按照工单自动在本地写代码、跑测试、自动化闭环；
- **控制权（人）**：人类创始人拥有最高拍板权与紧急刹车特权，全程可视化，绝无黑盒失控。

## 2. 行业前沿对标与技术借鉴剖析 (Industry Benchmarks & Deep Analysis)

为了确保本项目的技术先进性与产品领先地位，我们对当前开源界最顶尖的 5 个代表性项目进行了深度代码剖析与对比借鉴：

### 2.1 `garrytan/gstack` (YC 总裁兼 CEO Garry Tan 的一人软件工厂)
- **项目定位**：Garry Tan 个人每天都在高频使用的 AI 软件流水线。60 天内 solo 上线 3 个生产级服务、40+ 个功能，交付速度达传统手写时代的 810 倍。
- **底层实现**：完全基于 **Claude Code CLI**、**Codex CLI**、**Antigravity CLI** 等本地执行体之上构建。
- **可吸收与借鉴的精华**：
  1. **YC 级别产品问询 (`/office-hours`)**：当创作者提出 Idea 时，AI 不盲目顺从，而是像 YC 合伙人一样反思质问（Push back on framing），帮创作者把庞大臃肿的想法精简为“明天就能上线的最小切口 (Narrowest Wedge)”；
  2. **工程与安全严格规约 (`/plan-eng-review` & `/freeze`)**：在动工前锁死数据流与状态机，使用目录锁（`/freeze`）严禁 AI 越界误改无关文件；
  3. **跨大模型对撞仲裁 (`/pair-agent`)**：在 Claude 中调用 Codex 独立外部审查，在 Codex 中调用 Claude 对抗质询（Multi-AI Second Opinion）。
- **致命局限性（我们的机会）**：
  - **纯终端命令行（CLI）交互**：所有操作依赖终端敲斜杠命令（`/office-hours`、`/review`），依然是程序员的极客玩具，对普通独立创作者门槛依然极高，缺乏直观的可视化界面。

### 2.2 `anywhere-labs/Agents-Anywhere` (跨设备 Agent 工作台)
- **项目定位**：连接运行 Claude Code、Codex 的工作电脑，在 iPhone、Android 手机或 Web 端远程查看进展与审批任务。
- **底层实现**：在工作电脑后台运行 Python Connector，本质依然是调度本机的 **Claude Code CLI** 与 **Codex CLI / 本地 IPC Socket**。
- **可吸收与借鉴的精华**：
  1. **跨设备人机协同审批 (Human-in-the-loop Approval)**：把 CLI 遇到的权限询问、高危操作抽象为结构化的审批卡片，支持远程点按【批准】；
  2. **解耦的 Connector RPC 架构**：本地环境负责干活，上层负责推送会话与事件流。
- **致命局限性（我们的机会）**：
  - **仅为“单 Agent 远程监视器与对讲机”**：它没有多 AI 协同研讨（无双 PM 争论）、没有规范画布、没有工单拆解，无法从零孵化产品。

### 2.3 `yyjeqhc/webcodex` (ChatGPT 官方聊天本地工程运行时)
- **项目定位**：让 ChatGPT 官方网页端和客户端能够直接检查、修改本地电脑上的代码仓库。
- **底层实现**：利用官方标准的 **MCP (Model Context Protocol)** 协议，在本地启动 Server/Runner，通过 Cloudflare / OpenAI 安全隧道暴露 HTTPS 接口给 ChatGPT 开发者模式。
- **可吸收与借鉴的精华**：
  1. **官方聊天窗口直通本地代码**：不依赖脆弱的网页爬虫或按键精灵，完全通过官方合规的 MCP Tool Call（`read_file`、`git_status`、`execute_command`）穿透到本地；
  2. **会话完整保存在官方云端历史中**：用户在官方 ChatGPT 聊天框里打字，就能直接使唤本地工程。
- **致命局限性（我们的机会）**：
  - **仅仅是一个被动的工具通道**：缺乏主动指挥调度机制。它不能指挥工匠去分工跑阶段性开发，无法替代项目调度中枢。

### 2.4 `yetone/magpie` 与 `KKKKhazix/agent-autoloop`
- **可吸收精华**：Electron 原生持久化 Webview 隔离分区 (`persist:partition`)、任务自主循环执行回路（Task Auto-Looping）。

## 5. 核心功能实现规格说明 (Detailed Functional Specifications)

### 5.1 战略研讨室 (War Room - 双 PM 联合推演)
1. **联合司令部协同机制**：
   - 用户发送一条需求，系统同时调用 **Claude** 与 **ChatGPT**；
   - **Claude (融入 gstack 的 /office-hours)**：主动反思提问，识别痛点，梳理核心功能，做减法提炼最小可行版本（MVP）；
   - **ChatGPT (融入 gstack 的 /plan-eng-review)**：进行严苛的技术与边界核查，排查并发冲突与安全隐患；
   - 研讨完成后，右侧 Canvas 自动生成《双脑共识架构与开发规范书 (SPEC)》。
2. **单兵深入咨询通道**：
   - 随时一键切换为“仅找 Claude”或“仅找 ChatGPT”，针对某个特定难点进行一对一深度交流。
3. **真实模型动态探测 (Zero Guesswork)**：
   - 系统启动时通过 `/api/cli-models` 实时读取本机实际安装的模型列表（如 `gemini-3.8-flash-high`、`gpt-5.6-sol`、`claude-sonnet-5-5` 等），彻底消灭假模型。

### 5.2 创作者双特权通道 (Human-in-the-Loop)
1. **🔴 紧急暂停通道 (Emergency Pause)**：
   - 界面显眼位置设有“暂停”控制，点击即可触发硬中断（通过系统信号向后台执行子进程发送挂起/终止信号）；
   - 创作者可随时插入话语、纠偏方向后再恢复施工。
2. **🟡 里程碑确认机制 (Milestone Checkpoint)**：
   - 双脑推演完成后，绝不擅自动手写代码；
   - 界面弹出阶段性里程碑确认卡片，展示工单列表与预估改动；
   - **只有当创作者亲自点击【批准开工 (Approve)】**，工单才会正式推入执行流。

### 5.3 规范文档画布与任务看板 (Canvas & TaskBoard)
1. **共识规范画布 (Canvas)**：
   - Markdown 规范渲染；
   - 支持【对比 (Diff)】与【源码 (Source)】模式无缝切换；
   - 自适应响应式工具栏，保障分屏窄屏下按钮不折行、不被挤压。
2. **三态工单看板 (Task Board)**：
   - 将 SPEC 拆解为明确卡片：待办 (Backlog)、施工中 (In Progress)、已完成 (Done)；
   - 卡片上直观标注指派执行体（Cursor / Antigravity）、执行耗时与脱水简报。

### 5.4 底层执行体监控 (Live Worker Runner)
1. **多标签隔离监控**：
   - 汇聚总流 + Cursor Agent、Antigravity、Claude Code、Codex 独立 Tab；
   - 实时输出真实的标准输出（stdout）与错误输出（stderr）。
2. **日志脱水与极简规范**：
   - 剔除所有冗余无用的机器包装；
   - 遵循用户要求的高清晰度格式：直接输出 `Antigravity：“...”`、`Cursor：“...”`。

### 5.5 双模工作视界 (Dual View Studio)
1. **联合中枢模式 (War Room Studio)**：三栏分层工作台（侧栏项目树 + 参谋部研讨 + 画布与执行流）。
2. **官方原生并排视界 (Official Webview View)**：
   - 利用 Electron 的持久化 Session (`persist:ai_solo_claude` 与 `persist:ai_solo_chatgpt`)，内嵌官方原生 `claude.ai` 与 `chatgpt.com`；
   - 支持免额外登录复用网页端 Plus / Pro 订阅；
   - 提供“一键复制工程上下文”与“网页方案一键导入回中枢 Canvas”快捷按键。

### 5.6 项目级轻量 MCP 隧道服务 (Project MCP Bridge) —— *吸收 WebCodex*
1. **单项目 MCP 服务**：
   - 允许 Studio 为当前选中的工程目录暴露一个轻量级本地 MCP 端点；
2. **官方聊天直通本地**：
   - 用户可将生成的临时 MCP 链接直接配置到 ChatGPT 官方网页的开发者模式中；
   - 创作者在官方聊天窗口打字时，官方 ChatGPT 云端模型可通过 MCP 直接读取当前项目的目录结构与代码，实现官方聊天界面的本地代码感知。

### 5.7 跨设备远程审批中继 (Remote Approval Relay) —— *吸收 Agents Anywhere*
1. 规划在后续版本中引入轻量 Web / 移动端中继：
   - 创作者在电脑启动施工后，即使离开电脑，也能在手机端收到“里程碑审批卡片”并一键批准开工。

## 6. 技术实现铁律与工程基准 (Technical Guardrails)

1. **自带订阅原则 (BYOS)**：优先复用本机合法已安装的官方 CLI 工具（`agy`、`cursor`、`claude`、`codex`），零额外商业 API 计费；
2. **目录安全锁 (`/freeze`)**：派发任务给底层执行体时，强制限定工作区边界，严禁修改当前项目外的文件；
3. **真实探测原则 (Zero Guesswork)**：通过接口动态读取可用模型，严禁在前端界面硬编码虚构模型；
4. **非交互式安全参数**：调用本地 CLI 时注入 `--dangerously-skip-permissions`、`--trust` 等免阻塞参数，并设置 90 秒合理超时，超时后如实报错，严禁用伪造占位符掩盖；
5. **代码健康与工程验证**：保持 `npm run build`、`tsc --noEmit` 持续构建全绿。
